# AGENT.md - px0 Project Architecture & Memory

## Structure
- `src/index.ts`: Core Hono worker app (`/`, `POST /api/paste`, `DELETE /api/paste/:id`, `GET /raw/:id`, `GET /:id`, `/favicon.ico`), static asset routes (`/static/landing.js`, `/static/viewer.js`), security headers middleware, Web Crypto AES-256-GCM E2EE decryption, zero-knowledge PBKDF2 + AES-GCM password protection, server-side Markdown parsing via `marked` combined with `sugar-high` ~1KB lexical code syntax highlighting, custom SVG TTL dropdown, expiry countdown via KV metadata (`readPaste`), instant-delete footer API, and Burn-After-Read self-destruction mechanism.
- `src/client/`: Dedicated TypeScript client-side code (`src/client/landing.ts`, `src/client/viewer.ts`, `src/client/shared.ts`) compiled via `bun build --target=browser --outdir=public --minify` into static assets. `viewer.ts` drives the live expiry countdown (`startExpiryCountdown`), delete-button flow (`bindDeleteButton`), and password/E2EE unlock. `landing.ts` handles the padlock password toggle (auto-copies generated password to clipboard), a copy-password button (`copyPassBtn`), and the share **banner** (`showShareLink(url, isBurn)`) that displays the full `origin + /id` URL for every creation flow.
- `src/client/shared.ts`: Code used by both the worker and the browser. Owns the **single** markdown renderer `renderMarkdown()` (marked + sugar-high + `sanitizeOutputHtml`) imported by `index.ts`, `landing.ts` and `viewer.ts`, plus `formatTimeLeft`, `deriveKeyFromPassword`, `generate8CharPassword`, `base64UrlToBytes`, and the `copyToClipboard`/`flashCopied` clipboard helpers (async clipboard API with `execCommand` fallback).
- `src/utils.ts`: `generateShortId`, `sanitizeHtml`, `decodeBase64Url`, `bytesToBase64`, `bytesToBase64Url`, `getTtlSeconds`, `TTL_MAP`, `THIRTY_DAYS_IN_SECONDS`, `MAX_PASTE_BYTES`, and the storage sentinels `BURN_PREFIX` / `PASS_PREFIX` / `ENC_PREFIX`.
- `src/icons.ts`: Reusable inline SVG icons (`brandIcon`, `faviconSvg`, `splitIcon`, `lockIcon`, `saveIcon`, `trashIcon`, `clockSvg`, `globeSvg`, `flameSvg`, `chevronDownIcon`, `checkIcon`, `plusIcon`, `copyIcon`, `linkIcon`, `rawIcon`) eliminating inline SVG duplicates and all emoji from UI. Icons are **sized by their container** (`.btn-action svg`, `.badge svg`, `.unlock-icon-container svg`), never by per-copy `width`/`height` variants.
- `src/styles.ts`: Centralized CSS module exporting `CSS_VARIABLES`, `BASE_CSS`, `MARKDOWN_CSS`, `LANDING_CSS`, `VIEWER_CSS`, and `NOT_FOUND_CSS`. `CSS_VARIABLES` holds the design tokens — each accent ships as a `--x`/`--x-fill`/`--x-line` trio so a badge's text, background and border can never come from different colours — plus `--control-h`, `--mono` and the radius scale. `BASE_CSS` owns everything shared by both pages (header, footer, `.btn-action`, `.btn-save`, `.badge*`, one global `:focus-visible`); page-specific modules must not redefine them.
- `biome.json`: Biome single-dependency zero-config linter and formatter configuration.
- `test/index.test.ts`: Bun unit test suite covering utilities, API input validation, payload size limits, custom TTL options, Burn-After-Read self-destruction, Password Protection (`PASS:`), security headers, E2EE formatting, raw route handlers, and `formatTimeLeft`.
- `e2e/pastebin.spec.ts`: Playwright E2E test suite (13 tests) running full real-browser integration tests for landing page UI, Tab key handling, Plaintext creation, Web Crypto E2EE decryption, hash fragments, Password Protection & PBKDF2 decryption, custom TTL dropdown, Burn-After-Read self-destruct, multi-language syntax highlighting, viewer footer delete, 404s, and security headers.
- `playwright.config.ts` & `test/e2e-server.ts`: Playwright configuration and lightweight native Bun e2e test server runner.
- `wrangler.json`: Cloudflare Workers manifest binding `PASTES_KV` KV namespace.

## Critical Blunders & Technical Learnings
- **Hono HTML Tagged Template JSON Escaping:** Interpolating JSON in Hono `html\`...\`` auto-escapes quotes into `&quot;`. Fix: Wrap script data in `${raw(safeJsonData)}` and parse safely via external `/static/*.js`.
- **Hono Regex Backslash Stripping:** Inline JS regex literals inside Hono template strings lose backslashes during compilation. Fix: Bundle client JS via `bun build` served as `/static/*.js`.
- **Base64URL 43-Char Key Padding:** Web Crypto 256-bit raw keys output 43 chars without `=` padding; browser `atob()` throws `DOMException`. Fix: Restore missing `=` padding via `decodeBase64Url(str)`.
- **Uint8Array Spread Stack Overflow:** `String.fromCharCode(...bytes)` throws `RangeError` on payloads >32KB. Fix: Use character-looping helper `bytesToBase64(bytes)`.
- **Uint8Array Buffer Offset Slicing:** Passing `iv.buffer` on `combinedBytes.slice(0, 12)` passes the underlying parent ArrayBuffer to Web Crypto `decrypt()`. Fix: Pass Uint8Array view `iv` directly into `decrypt({ name: 'AES-GCM', iv })`.
- **DOM ReadyState Script Execution Timing:** Deferred scripts (`<script defer>`) can execute when `readyState` is already `'interactive'`. Fix: Check `if (document.readyState === 'loading') { addEventListener('DOMContentLoaded', fn); } else { fn(); }`.
- **Password Modulo Bias:** Raw byte modulo on character sets produces non-uniform entropy. Fix: Implement rejection sampling in `getUniformRandomChar()`.
- **Rate Limiter Memory Leak:** Unpruned Map entries cause memory leaks under IP floods. Fix: Implement size-threshold pruning helper `pruneRateLimitMap()`.
- **sanitizeHtml Before Markdown Parse (F1):** Escaping `>` to `&gt;` before `marked.parse()` breaks blockquotes. Fix: Parse markdown first, then post-sanitize rendered HTML via `sanitizeOutputHtml()`.
- **Prefix Collision (F2):** Storing plaintext verbatim means user content starting with `PASS:`, `ENC:`, or `BURN:` triggers wrong control flow. Fix: Use unambiguous sentinel prefixes `__PX0_BURN__:`, `__PX0_PASS__:`, `__PX0_ENC__:`.
- **CSP unsafe-inline (F3):** Inline `<script>` IIFE and `onclick` attributes required `'unsafe-inline'` in CSP `script-src`. Fix: Move data init into `viewer.js` via `data-*` attributes on `<script id="px0-data">`, bind clicks via `addEventListener`.
- **Regex Highlighter Nesting (F8):** Sequential regex replacements in `highlightCode` colour keywords inside strings/comments. Fix: Single-pass tokeniser regex matching strings/comments before keywords.
- **bytesToBase64 Perf (F12):** Character-by-character `String.fromCharCode` loop creates O(n) intermediate strings. Fix: 8KB chunked `String.fromCharCode.apply`.
- **KV Expiry Not Readable via `get`:** A single KV `get`/`getWithMetadata` never returns a key's expiration. Fix: store `{ createdAt, ttlSeconds }` as KV metadata on write; compute `expiresAtMs`. For legacy pastes (no metadata), fall back to `list({ prefix: id, limit: 1 })`, whose keys expose `expiration` (Unix seconds).
- **`getWithMetadata` vs `get(..., { metadata: true })`:** The `@cloudflare/workers-types` KV typing only resolves `{ value, metadata }` through the dedicated `getWithMetadata()` overloads; `get()` with `metadata: true` collapses to `string | null` and fails `tsc`.
- **Native `<option>` Can't Hold SVG:** `select`/`option` only render text, so emoji/icon glyphs look inconsistent and unstylable. Fix: build a custom dropdown (`div.ttl-dropdown` + button trigger + `ul.ttl-menu` with `role="listbox"`), backed by a hidden `<input id="ttlInput">`, with click/outside/Escape handlers in `landing.ts`.
- **Emoji Renders Inconsistently (cross-platform & CSP-hostile):** Replaced all UI emojis (`🔒🌐🔥⏳❌⏱️📅`) with inline SVG icons in `src/icons.ts`; badges use `display:inline-flex; gap` for icon/text alignment.
- **Viewer Status Badge Relocated:** The E2EE/Plaintext/Password status badge lives in the viewer **footer** (next to the Delete button), not the header; the header keeps the TTL countdown and burn badges.
- **Burn-After-Read Must Not Burn on Creator Redirect:** Auto-redirecting the creator to `/{id}` after creating a burn paste consumes the burn, making it unreadable/shareable. Fix: **every** creation flow (burn, password, E2EE, any TTL) now shows the same share-link overlay (`createShareLink`) and never navigates; a burn paste is only consumed on the first *reader's* view.
- **Unify Creation Redirect UX:** Non-burn pastes used to `window.location.href` after saving while burn pastes got an overlay — a UX inconsistency. Fix: `showShareLink(url, isBurn)` drives all flows to one overlay (burn icon/title for burn, link/title "Paste created" otherwise); the `burn-share-*` CSS/IDs were renamed to generic `share-*`/`#shareUrl`/`#copyShareBtn`/`#createNewBtn`.
- **Badges Must Never Lie About Encryption:** Two related bugs. (1) The viewer's password badge rendered the lock SVG *only* while E2EE/Plaintext kept text labels — inconsistent, and it read as a decoration rather than a security state. (2) Worse, on the landing page selecting a password switched the footer badge to **"Plaintext" + globe**, even though the payload is PBKDF2 + AES-GCM encrypted. Fix: three explicit modes (`e2ee` / `password` / `plaintext`) in a single `MODES` table in `landing.ts`; password mode is green/`badge-encrypted` and labelled "Password" on both the landing footer and the viewer footer.
- **Burn Share Link Needs E2EE Hash:** A burn paste created in E2EE/plaintext mode must carry its `#key` hash in the share link so the recipient can decrypt; the overlay includes the full origin + path + hash.
- **Relative-Only Values in Share Overlay:** The burn/share `<input>` originally displayed a relative `/id` path while the copy handler produced the full URL — inconsistent UX. Fix: compute `fullUrl = origin + url` once and use it for both the displayed `value` and clipboard copy.
- **Clipboard Write Fallback:** `navigator.clipboard.writeText` throws/undefined on non-HTTPS or insecure contexts. Fix: a single `copyToClipboard()` helper in `landing.ts` falls back to a hidden textarea + `document.execCommand('copy')`.
- **Auto-Copy on Password Generation:** The padlock toggle (OFF→ON) generates a fresh 8-char password via `generate8CharPassword()`; auto-triggering `copyToClipboard()` there drops the password straight into the user's clipboard, plus a dedicated `.inline-pass-copy` button for manual re-copy.
- **Gate Footer Delete Behind Unlock:** Header copy/raw/delete actions were correctly hidden for password/E2EE pastes, but the footer **Delete button still rendered** unconditionally — exposing a destructive action before the paste was unlocked. Fix: `deleteBtn` gets `style="display:none"` server-side when `isPasswordProtected || isEncrypted`, and `revealPasteActions()` (called only after successful decrypt/unlock) restores it via `deleteBtn.style.display = "flex"`.
- **The Share Banner Must Not Carry an Overlay Class:** The banner was converted from a modal to an in-flow row, but `showShareLink` kept setting `className = "header-share-banner share-overlay"`. `.share-overlay` was still `position: fixed; inset: 0; backdrop-filter: blur(8px)`, so the "non-modal" banner rendered as a full-screen sheet that blurred and blocked the whole editor — three floating controls on a black page. Fix: the banner sets only `header-share-banner` (+ `is-burn`), and every `.share-overlay`/`.share-card`/`.share-icon`/`.share-url`/`px-fade-in` rule was deleted so the class cannot be reapplied. Regression-guarded in e2e by asserting `#headerShareBanner` has `position: static` and `#content` stays visible.
- **One Markdown Renderer, Not Two:** The server rendered with `marked` + `sugar-high` while the browser used a hand-rolled `parseMarkdown` in `shared.ts`. Since **E2EE is on by default**, the default paste path rendered through the weaker parser, which had no table support at all — so a table silently vanished in the live preview and in every decrypted E2EE/password paste, while plaintext pastes rendered it fine. Fix: one `renderMarkdown()` in `src/client/shared.ts` (marked + sugar-high + `sanitizeOutputHtml`) imported by `index.ts`, `landing.ts` and `viewer.ts`. Costs ~15KB gzip on the client; buys identical output on every surface and deletes ~130 lines of parser. Its old double-escaping bug (escaping the whole string before splitting code fences) is gone with it — `renderMarkdown` unescapes entities only inside `<pre><code>` before handing them to `highlight()`.
- **`hashchange` Re-Ran the Entire Viewer Init:** `window.addEventListener("hashchange", initPageViewer)` re-ran everything on any fragment change. That stacked a duplicate `deleteBtn` click listener and a second countdown `setInterval` per event, and — worst — re-rendered the unlock card over already-decrypted content, so following an in-page `#heading` link on an unlocked password paste demanded the password again. Fix: the hash only ever carries the E2EE key, so the listener now re-inits only when `isEncrypted && !__PX0_DECRYPTED_TEXT__`; `bindDeleteButton` and `startExpiryCountdown` additionally guard on `dataset.bound` / `dataset.ticking`.
- **Interactive Code Block Copy & Password UX:** Added hover-triggered `.code-copy-btn` to viewer code blocks, instant visual feedback flash on password auto-copy, and cleared password error messages upon typing.
- **Hono `html` Template Object Bundling & Non-Modal Top Share Banner:** Importing `html\`...\`` from `hono/html` into client-side JS bundled server runtime objects into browser JS, breaking `.innerHTML` stringification on mobile browsers. Fix: Convert `src/icons.ts` to pure plain string SVGs (`${raw(icon)}` on server). Built Option 2 (Top Notification Banner) attached directly underneath `<header>` for non-modal, collision-free, mobile-friendly share creation UX with 100% editor canvas visibility.
- **Badge Colours Must Come From One Token:** `.badge-public` set `color: var(--accent)` (amber) against an `rgba(88,166,255,…)` blue fill and border — amber text in a blue pill. `--accent` and `--amber` were also duplicate names for `#d29922`. Fix: `--accent`/`--accent-glow` deleted; each semantic badge (`badge-encrypted`/`badge-public`/`badge-ttl`/`badge-burn-once`) draws text, fill and border from one colour family (`--green|blue|amber|red` + matching `-fill`/`-line`). e2e asserts `.badge-public` computes to `rgb(88,166,255)`.
- **GFM Output Needs Matching CSS:** `marked` emits tables, task-list checkboxes and images that `MARKDOWN_CSS` never styled, so tables rendered as unaligned floating cells and task lists showed raw grey OS checkboxes. Fix: added `table`/`th`/`td` rules (collapsed borders, zebra rows, `overflow-x:auto` so wide tables scroll instead of breaking the page), `img { max-width:100% }`, custom amber `input[type=checkbox]`, and nested-list margins.
- **One Control Height:** `.btn-action` was 32px in `BASE_CSS`, overridden to 36px inside the share banner and 38px in the share card, so buttons on the same row disagreed. Fix: a `--control-h` token drives `.btn-action`, `.btn-save`, `.btn-delete`, `.ttl-trigger`, `.share-banner-badge` and `#shareUrl`; the per-context overrides are gone. A single `:focus-visible` rule in `BASE_CSS` covers every control (previously only `.ttl-trigger` had one).
- **Don't Duplicate Helpers Across `utils.ts` and `client/shared.ts`:** `decodeBase64Url`, `bytesToBase64` and `bytesToBase64Url` existed in both, and the two `decodeBase64Url` copies had *diverged* — only the `shared.ts` one stripped whitespace/padding. `sanitizeHtml` (utils) and `escapeHtml` (shared) were the same function under two names. Fix: `src/utils.ts` is the single home (keeping the lenient decoder); `shared.ts` re-exports and adds `base64UrlToBytes()`, which returns `Uint8Array<ArrayBuffer>` so it drops straight into WebCrypto without a `BufferSource` cast.
- **`required` Silently Killed the Inline Save Error:** The textarea carried `required`, so an empty submit was stopped by the browser's own validation bubble *before* the submit handler ran — `#saveError` and its "editor is empty" branch were unreachable dead code, and the bubble rendered unstyled at the bottom of the page. Fix: drop `required`; the handler owns validation.
- **A Listbox of `<li>`s Is Mouse-Only:** `.ttl-option` elements had `role="option"` but no `tabindex`, no arrow-key handling and no focus return, so the expiry control could not be operated from the keyboard at all. Fix: roving `tabIndex = -1` set in `landing.ts`, ArrowUp/Down/Home/End/Enter/Space/Escape/Tab handlers, and focus returns to the trigger on select. Uncovered a second bug while testing it: the default option carried only `aria-selected` in the server markup, never the `.selected` class the checkmark CSS keys off — so the menu showed **no** checkmark until the user changed TTL. Fix: `setTtlOption()` now reads its label off the chosen option (one source of truth for label + hidden input + checkmark) and is called once at init.
- **Opacity-0 Is Not Hidden:** The collapsed `.inline-pass-bar` used `opacity: 0; max-width: 0` only, so Tab still landed in an invisible password field. Fix: add `visibility: hidden` to the collapsed state. Relatedly, `.toggle-e2ee input` was `width: 0; height: 0`, which drops a control out of Chrome's accessibility tree entirely — the encryption switch was invisible to screen readers. Fix: 1px, not 0.
- **A Badge That Is Secretly a Switch:** The footer E2EE badge is a `<label>`-wrapped checkbox, but nothing distinguished it from the viewer's read-only status badges, so Plaintext mode was undiscoverable. Fix: a CSS `::after` caret and a hover brightness lift on `.toggle-e2ee .badge`, both suppressed when password mode disables the control.
- **Clearing a Password Overrode a Deliberate Plaintext Choice:** `syncPasswordState()` hard-set `e2eeToggle.checked = true` whenever the password emptied, so Plaintext → password on → password off silently re-enabled E2EE. Fix: remember the user's pick in `wantsE2ee` and restore that.
- **Burned Pastes Rendered Dead Controls:** A burn-after-read paste is deleted during the very request that renders it, yet the viewer still drew Copy Link, View Raw (both 404) and Delete (nothing left to delete). Fix: `isBurnAfterRead` omits all three server-side; Copy Content stays, since the text is still in the page.
- **Placeholder Contrast:** `--text-dim: #484f58` on `--bg` is 2.1:1 — the editor's only usage hint was effectively unreadable. Now `#7d8590` (~5:1).
- **Header Had No Wrap:** brand + password bar + split + TTL trigger need ~410px; below that (any 375px phone) the landing page's `overflow: hidden` simply clipped the TTL control off-screen. Fix: `flex-wrap: wrap` on `header` and `.header-right`.
- **`\s+on[a-z]+=` Misses `/` Separators:** HTML accepts `/` between attributes, so `<img/onerror=…>` walked past `sanitizeOutputHtml`. (CSP `script-src 'self'` still blocked execution — this is the defence-in-depth layer.) Fix: `[\s/]+`.
- **Never `alert()` on Save Failure:** A failed save fired a blocking browser dialog, and a *network* failure threw past the handler entirely, leaving the Save button stuck disabled with no explanation. Fix: an inline `#saveError` element in the footer, a `fail()` helper that always re-enables the button, and a `try/catch` around the `fetch`. `:disabled` styling moved from inline `style.opacity` into CSS. Ctrl/Cmd+S is now actually bound — the button's tooltip had advertised it all along.
